## 2. 연계 데이터 플로우 — front 노출 결정 공식

front에 콘텐츠가 노출되려면 **admin 설정 5조건을 모두(AND) 만족**해야 하며, 노출되는 내용은 **고객 언어의 번역본**이다.

```
front 노출 = 노출여부(ON)
           ∧ 게시기간(시작일 ≤ now < 만료일 또는 무기한)
           ∧ 적용국가 ∈ {고객 국가, 🌍전체}
           ∧ 상태(공지/가이드=노출, 업데이트=반영완료)
           ∧ 솔루션(지정 솔루션 탭/전체)
표시내용   = 고객 언어 번역본 (저장형: 원문 저장 → 일괄번역 → 번역데이터 저장)
```

- **적용국가의 이중 역할**(ISSUE-063): ① 노출 대상(배포 클럽) ② 번역 언어 — 둘 다 적용국가에서 파생. 예) 미국만 지정 → 미국 클럽에만 노출 + 영어 번역본.
- **업데이트 `반영완료`** = front 노출 게이트(서버가 status 필터링). `반영대기`는 admin 전용.

## 5. 검증 시 고려 필요 사항 (핵심)

### 5-1. 테스트 가능성 제약 (가장 중요)

**진짜 end-to-end(admin에서 생성 → front에서 확인)는 현재 자동화로 닫을 수 없다.**

| 제약 | 내용 | 검증 전략 |
|---|---|---|
| admin 목업엔 **백엔드 없음** | `smartscore_admin_v0.3.html`은 정적 파일 — 저장해도 DB·front로 전파 안 됨 | admin은 **UI/정책 정합성만**(목업 자체 검증). front로의 전파는 불가 |
| 실 admin = **내부관리자(mng)** | `cc.smartscore.kr/ss/mng`, 국내 담당자 권한 + 로그인. 쓰기 = **실데이터 파괴** | 자동화 **쓰기 금지**. 생성 플로우는 수동/시드 데이터로만 |
| front는 **라이브(읽기)** | 우리가 자동화하는 대상. admin이 넣은 결과를 **관측만** 가능 | front에서 **AS-IS 관측 + 정책 기대값 대조**(2축). 역방향 생성 트리거 불가 |
| 공유 QA 세션 | 재로그인 1회당 1런 ([session-one-run-per-login]) | front 라이브 런은 단일 test 순회·재인증 선행 |

> **결론**: 연계 검증은 "admin에서 X 설정 → front에서 Y 결과"를 **직접 트리거**하는 대신, **front에 이미 존재하는 데이터가 정책(연계규칙)과 일치하는지**를 관측·대조하는 방식(단방향 관측)으로 설계한다. admin 쪽은 목업 UI를 **정책 정합성**으로 별도 검증(생성→전파 아님).

### 5-2. 드리프트/불일치 우선 점검 (admin↔front 교차)

| # | 점검 포인트 | 판정 |
|---|---|---|
| D1 | **수정 저장 미반영 결함**(2026-09-02) — 제목·본문 외(노출여부·게시기간·적용국가·솔루션)는 admin 수정 저장이 미반영(1차 한정) | **실결함/드리프트 최대 원천.** front 관측값이 admin 의도와 어긋나면 이 결함부터 의심 |
| D2 | **솔루션명 "무전" vs "무전기"** — 정책/태그풀은 "무전", 라이브 front 탭은 "무전기" | **드리프트 확정**(prior diff). admin 목업은 "무전" 사용 → front "무전기"가 이탈 |
| D3 | **솔루션 나열 순서 3곳 상이** — admin 필터 / front 가이드 탭 / front 홈 그리드 | 구성 11개 동일·**순서만** 다름. 결함 아닐 수 있으나 명시 확인 |
| D4 | **문의 완료 배지 색상** — admin gray vs front green(문서상) | 교차검증, 실화면 실측으로 확정 |
| D5 | **상태 라벨 노출 비대칭** — 업데이트 "반영완료" 텍스트는 admin만, front 미노출 | **정상**(의도적 차등). front에 상태텍스트 있으면 오히려 이상 |
| D6 | **날짜/기간 표기 차등** — admin=라벨+기간+'무기한', front=라벨없이 날짜(범위) | **정상**(의도적 차등) |
| D7 | **시간대 환산** — front는 현지환산 아님, KST원본+"KST" 라벨(보류) | **정상/보류**. front에 "환산됨"이 보이면 이상(ISSUE-079) |
| D8 | **태그 번역 미결** — 다국어 front 태그 표시/필터 거동 미확정 | 미결. 다국어 front 검증 시 태그는 판정 보류 |
| D9 | **FAQ 홈 위젯 정적 목업** — 가이드 연동은 FAQ 전체보기 페이지만 | 홈 위젯 FAQ는 연동 대상 아님 |
| D10 | **문의 상태 2단계 회귀** — 과거 front 대기/완료 2단계였음, 현재 3단계 통일 | front가 2단계로 보이면 **회귀 결함** |

### 5-3. 2축 검증 전략 적용 (기존 하네스 원칙 계승)

- **검증축(PASS/FAIL)**: front 락케이터·기대값을 **현 구현(AS-IS)** 기준 — 가짜 FAIL 제거.
- **추적축(INFO/diff)**: 기획(policy)-구현 차이는 결함 아닌 `diff()`로 기록 → 리포트 `기획-구현 차이` 시트. D2(무전기)·D3(순서)·D4(색상) 등이 여기 해당.
- **연계 전용 체크**: front 관측값이 **연계 공식(§2)** 과 모순되는지 교차 검증(예: 적용국가=한국단독 공지가 타국 언어로 보이면 모순 / 반영대기 상태가 front에 보이면 모순).

## 6. 검증 설계 제언 (연계 관점)

### 6-1. 콘텐츠 4종 (단방향 — front 관측 + 정책 대조)
- front 목록/상세에서 **노출여부·게시기간·적용국가·솔루션·상태**가 §2 공식과 정합한지 관측.
- 경계 시드 활용: IA 실측에서 확인된 "(시험) 적용국가 한국단독 공지 / URL 토큰 표본 / 제목 최대길이 표본" → 경계값 검증.
- admin 목업은 별도로 **폼 유효성·블록 에디터·임시저장·번역 탭** UI 정책 정합성만(생성 전파 아님).

### 6-2. 문의 (양방향 — 가장 복잡)
- **상태머신 3단계**(대기→진행중→완료) 공유, 재오픈 복귀 규칙, 완료 후 새 티켓 분리.
- **10초 폴링 실시간 반영**은 실서비스 스펙(프로토타입·라이브 모두 타이머 코드 유무 확인). 자동화로 admin↔front 동시 관측은 세션·쓰기 제약으로 **수동 시나리오** 권장.
- 비파괴 원칙: front에서 **새 문의 접수·추가 질문·완료 처리 등 쓰기 동작 금지**(관측·필터만).

### 6-3. 번역 (저장형)
- front 언어 전환 시 **번역본 표시**(원문 비노출) 관측. 태그는 미결(§D8)로 판정 보류.
- 재번역 트리거(수정 시 전체 덮어쓰기)는 admin 쓰기라 자동화 대상 아님 — 정책 인지만.

## 7. 미결·보류 (검증 전 확인 요망)

1. **지원 언어 확정** 미결 → front 언어 선택기 8개 언어 ↔ 운영 11개국 매핑 불일치(ISSUE-079). 시간대 환산·태그 번역 모두 여기 묶임.
2. **수정 저장 반영 범위**(제목·본문만, 나머지 후속) — 1차 한정 결함, 확장 예정.
3. **문의→FAQ 승격** 1차 제외(ISSUE-108). FAQ 출처는 가이드 유일.
4. **조회수 트래킹 인프라** 부재 — FAQ 조회수 `—`.
5. admin 실서비스 접근(mng) 자동화 범위·쓰기 가능 여부 — **현재 스코프 밖**(front 라이브 관측 중심).
