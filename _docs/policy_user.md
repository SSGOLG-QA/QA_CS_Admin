# CS 고객 화면 정책 (policy_user.md)

고객(골프장 관계자)에게 노출되는 `smartscore_cs.html` 화면의 표시 정책을 정의합니다.

## 접근 정책 (2026-08-05 확정)

| 항목      | 정책                                                                     |
|-----------|---------------------------------------------------------------------------|
| 접근 경로 | **클라우드 로그인 후 좌측 사이드바 '이용가이드' 버튼 클릭 시 접근 가능**  |
| 권한      | 클라우드 로그인한 사용자라면 별도 서비스 권한 없이 모두 접근 가능         |

## 클라우드 진입 화면 (2026-07-29 반영, 2026-08-21 문구 정리)

- `smartscore_cs.html`의 첫 화면은 **클라우드 포털 목업**(`#cloud-portal`, 좌측 사이드바 + 대시보드/솔루션 카드)이다. 고객(골프장 관리자)의 실제 접근 경로가 cloud.smartscore.kr이므로 이 화면은 그대로 유지한다.
- 좌측 사이드바 하단의 **"이용가이드"** 클릭 시 클라우드 포털이 사라지고 실제 cs.html 화면(`#cs-app`, 홈부터 시작)이 노출된다.
- 사이드바의 대시보드·계정설정·마이페이지·고객성공 등 다른 메뉴는 클릭 시 하이라이트만 되는 목업 상태이며, 실제 이동 기능은 없다.
- 이 구조는 실제 서비스의 "클라우드 로그인 → 좌측 사이드바 '이용가이드' 클릭 → CS 진입" 흐름을 화면으로 보여주기 위한 것이며, 실제 인증·로그인 로직은 포함하지 않는다.
- **admin 쪽 동일 구조는 제거됨(2026-08-21)** — admin의 실제 접근 경로는 클라우드가 아니라 내부관리자(`cc.smartscore.kr/ss/mng`)이므로, `smartscore_admin_v0.3.html`에 있던 클라우드 포털 첫 화면(cs.html이 원래 이 구조를 그대로 재사용해 만들어졌음)은 실제 경로와 맞지 않아 삭제하고 admin 대시보드가 바로 보이도록 정리했다. `policy_admin.md`의 "CS Admin 접근" 참고

## 공지사항 정책

### 날짜 표시 — 목록·상세 공용 (2026-09-08 확정)

- **목록·상세 모두** 라벨 없이 날짜만 노출한다(예: `2025.06.08`) — "등록:" 같은 접두 텍스트는 붙이지 않는다. 상세페이지를 열지 않아도 목록에서 바로 게시 기간을 알 수 있어야 한다는 이유로, 상세에서만 보여주던 것을 목록에도 동일하게 적용
- 해당 공지에 **게시만료일이 설정된 경우**(admin `게시 만료일` 입력값)에는 `등록일 ~ 게시만료일 23:59` 범위로 노출한다: 예) 한국어 `2025.06.15 ~ 2025.07.15 23:59` / 그 외 언어 `2025.06.15 ~ 2025.07.15 23:59 KST` (2026-10-01 확정 — 만료일 뒤에 "23:59"를 고정 표기. 실제로 저장되는 시각 값은 아니고, "만료일 당일 23:59까지 유효"라는 내부 전환 기준을 고객에게도 그대로 문구로 보여주기 위함. "23:59"는 화면에 실제로 보이는 시각 표기이므로, "화면에 시:분이 노출되면 비한국어엔 KST 라벨을 붙인다"는 공통 원칙에 따라 한국어 조회 시엔 "KST" 라벨 없이, 그 외 언어 조회 시엔 라벨을 병기한다. 아래 "시간대 기준" 참고)
- **게시만료일이 없는(무기한) 공지**는 등록일만 노출하고, admin처럼 `무기한`이라는 텍스트를 별도로 붙이지 않는다 — 고객 입장에서는 "언제까지 유효한지"만 알면 되고, 굳이 만료일이 없다는 사실을 텍스트로 알릴 필요는 없다고 판단
- admin 쪽은 `게시 기간` 행에 `시작일 ~ 종료일` 또는 `시작일 ~ 무기한`으로 항상 기간 형태 + 라벨과 함께 노출(`policy_admin.md` "게시 만료일" 참고) — cs.html은 고객 대상이라 라벨 없이 날짜(범위)만, 만료일이 있을 때만 범위로 노출하는 방식으로 차등 적용
- 구현: `formatNoticePeriod(n)` 공용 함수로 목록(`renderNoticePage`)·상세(`showNoticeDetail`) 양쪽에서 동일하게 사용
- **시간대 기준(Q33, 2026-08-18 확정 · 2026-09-29 재정리 · 2026-10-01 재확정)**: 게시일은 서버에 **KST 기준으로 저장**되고 admin 화면엔 KST 그대로 노출된다. **공지사항 등록 폼 자체엔 시각 입력이 없어(날짜 전용 필드) 실제로 저장되는 시각 값은 없다.** 다만 고객 화면 표시 방식은 시작일과 만료일이 다르다(2026-10-01 확정):
  - **게시 시작일(등록일)**: 언어 무관하게 **항상 날짜만** 노출(위 "날짜 표시" 참고) — 보여줄 시각 값 자체가 없으므로
  - **게시 만료일**: 날짜 뒤에 **"23:59"를 고정 문구로 병기**(예: `2025.07.15 23:59`) — "만료일 당일 23:59 KST까지 노출, 그 이후부터 미노출"되는 내부 전환 기준을 고객에게도 그대로 알려주기 위함. 실제 저장된 시각 값은 아닌 **표시 전용 고정 문구**이며, 업데이트 배포일시(관리자가 실제로 입력하는 저장값)와는 전혀 다른 개념이다. 다만 **"화면에 실제 시:분이 노출되면 비한국어엔 KST 라벨을 붙인다"는 공통 원칙**은 둘 다에 해당하므로, 한국어 조회 시엔 "KST" 라벨 없이, 그 외 언어 조회 시엔 "KST" 라벨을 병기한다(국가별 현지시간 환산은 아님 — 최소한 "한국 시간 기준"임을 전달하는 목적)
  - 국가별 현지시간 환산은 적용하지 않는다 — 업데이트 배포일시와 같은 블로커(국가·언어 매핑 방식 미확정)로 보류 중(이 블로커 자체는 양쪽 공용)
  - (2026-09-29 당시엔 "만료일의 23:59도 고객에게 노출하지 않는 내부 기준일 뿐"이라고 서술했으나, 2026-10-01 고객에게도 "23:59"를 노출하는 쪽으로 재확정함. 이후 "언어 무관 KST 라벨 없음"으로 한 차례 더 정리했다가, 같은 날 "한국어 외 언어엔 KST 라벨 필요"로 최종 재확정 — 바로 위 "날짜 표시" 항목 참고)
  자세한 배경은 `policy_admin.md` "시간대(타임존) 정책" 참고

### 페이지네이션 (2026-07-28 반영)

- 목록 하단에 **페이지네이션**을 제공한다. 1페이지당 **30개** 노출.
- 솔루션 탭 필터 변경 시 1페이지로 초기화되며, 필터링된 결과 기준으로 페이지가 계산된다.
- 전체 건수 정보 없이 "이전 / 페이지 번호 / 다음" 버튼만 콘텐츠 영역 기준 **중앙 정렬**로 노출한다. 1페이지만 있어도 항상 노출한다.

## 업데이트 공개 정책

### 복수 솔루션 업데이트 탭 노출 정책

- 하나의 업데이트가 여러 솔루션을 포함하는 경우, **해당 솔루션이 속한 모든 탭에서 노출**한다.
- 예: ERP + 카트내결제가 묶인 업데이트 → ERP 탭, 카트내결제 탭 모두에서 표시됨
- **업데이트 페이지 전체 목록**에서 복수 솔루션 업데이트는 해당 솔루션 뱃지를 모두 노출한다(제목 아래 줄에 자동 줄바꿈, 개수 제한 없음).
- **홈 화면 위젯**(미리보기 카드)은 제목을 항상 **한 줄 + 말줄임표(...)**로 유지한다. 솔루션 뱃지는 **최대 2개까지만** 같은 줄에 노출하고, 그 이상은 `외 N개`로 요약한다(admin의 적용 국가 `~ 외 N개` 표기와 동일한 관례). `외 N개`에 마우스를 올리면 나머지 솔루션명이 툴팁으로 노출된다(2026-09-08 확정, `capUpdateSolBadges()`). 이전에는 제목과 뱃지가 같은 줄에서 폭을 다퉈, 솔루션이 많은 업데이트는 **제목이 거의 안 보이는 결함**이 있었음 — 처음엔 뱃지를 제목 아래 줄로 내리는 방식을 시도했으나(전체 목록과 동일 패턴) 사용자가 "제목은 말줄임표로, 뱃지는 한 줄에 외 N개로" 요청해 현재 방식으로 확정

### 배포일시 시간대 표시 (2026-09-29 갱신 — "게시 시작일" 명칭 변경, 2026-10-01 "배포일" → "배포일시"로 재수정 + cs.html 노출 방식 확정)

- 저장 기준은 공지사항과 동일 — **KST 기준으로 저장**
- **공지사항과 달리 배포일시는 날짜와 시:분을 함께 관리**한다(2026-09-29 확정, "업데이트 공개 정책" 등록 폼 참고 — 배포는 특정 시각에 이뤄지는 이벤트이기 때문). admin 화면엔 `YYYY.MM.DD HH:MM` 그대로 노출
- **cs.html(고객 화면)도 날짜+시:분을 노출한다**(2026-10-01 확정 — 기존 "미결" 상태 해소). 다만 "KST" 라벨 표기는 언어에 따라 다르다:
  - **한국어 조회 시**: `YYYY.MM.DD HH:MM` — "KST" 라벨 없음 (한국어 사용자에게는 불필요한 정보라 생략)
  - **그 외 언어 조회 시**: `YYYY.MM.DD HH:MM KST` — 아직 국가별 현지시간 환산이 안 되므로(아래 항목 참고), 최소한 "한국 시간 기준"임을 알리기 위해 라벨 병기
  - 목록(업데이트 페이지)·상세 모두 동일 기준 적용(`formatUpdateDateTime()`, `smartscore_cs.html`), 홈 화면 미리보기 위젯(`.u-date`)은 정적 마크업이라 이번 변경 범위 밖 — 날짜만 노출하는 기존 표시 유지
- 국가별 현지시간 환산은 이 필드에도 아직 적용되지 않음(위 "시간대(타임존) 정책" 미결 사항과 동일 블로커 — 국가·언어 매핑 방식 확정 필요)

### 고객 화면 노출 상태값

| 상태값   | 표시 라벨 | 고객 화면 노출 |
|----------|-----------|:--------------:|
| 반영완료 | 반영완료  | ✅ 노출        |

- 고객 화면(cs.html)에는 **반영완료** 상태의 업데이트만 노출한다.
- 반영 대기 중인 업데이트는 admin에서만 관리하며 고객에게 노출하지 않는다.
- 실제 서비스에서는 서버에서 `status = 반영완료` 조건으로 필터링하여 응답한다.
- **"반영완료" 상태 텍스트는 고객 화면에 노출하지 않는다.** 고객에게 노출되는 업데이트는 모두 반영완료 상태이므로 상태 표시가 불필요하다. (홈 목록, 업데이트 페이지 목록, 상세 페이지 모두 해당)

### 목록 노출 방식 — 더보기 (2026-07-28 반영)

- 업데이트(릴리즈 노트) 목록은 페이지네이션 대신 **"더보기" 버튼** 방식으로 노출한다.
- 최초 진입 시 최신순 10개를 노출하고, "더보기" 클릭 시 다음 10개를 이어서 추가 노출한다.
- 노출 가능한 항목을 모두 보여준 경우 "더보기" 버튼은 숨긴다.
- 솔루션 탭 필터 적용 시 노출 개수는 10개로 초기화되며, 필터링된 결과 기준으로 더보기가 동작한다.

## 문의 상세 정책

> **실시간 반영(2026-09-08 범위 확정 → 2026-09-14 구현 방식 확정)**: admin이 답변을 발송하면 이 화면을 열어둔 채로도 바로 반영되어야 한다는 요구가 있었고, 웹소켓/SSE 푸시가 아니라 **10초 주기 폴링**으로 확정됨(최초 30초 검토 후 10초로 조정). 이 프로토타입 파일 자체엔 백엔드가 없어 타이머 코드는 아직 없음 — 실제 서비스 구현 시 적용할 스펙. 트리거 조건은 `policy_admin.md` "문의 상세 스레드 실시간 반영" 참고.

### 채팅방 UI

- 문의 상세는 **채팅방 형태**로 표시한다. 사이드바 없이 채팅 스레드만 노출한다.
- 메시지 방향: 고객 메시지는 **좌측(회색 버블)**, CS 팀 답변은 **우측(파란 버블)**으로 표시한다.
- 메시지마다 발신자(`나` / `CS 팀`)와 시각을 표기한다.
- **CS 팀 메시지 회수·수정 시**(admin에서 운영자가 처리, `policy_admin.md` "관리자 발신 메시지 회수·수정" 참고): 회수된 메시지는 내용 없이 `회수된 메시지입니다`로만 표시하고, 수정된 메시지는 시각 옆에 `(수정됨)` 표기를 노출한다(2026-08-28 확정 — ISSUE-101, 1차 구현)

### 추가 문의 입력 영역

- 글자 수 제한 없음 (maxlength 미적용)
- 이미지 첨부 가능: 이미지 버튼 클릭 → 로컬 파일 선택 → 섬네일 미리보기 표시
- 여러 장 동시 첨부 가능(**최대 5장**), 섬네일에서 개별 삭제 가능
- 허용 포맷: .jpg / .jpeg / .png
- 파일 크기 제한: 개당 최대 10MB
- 범위 초과 시 알럿 표시 (포맷 오류 / 용량 초과 / **5장 초과** 각각 안내)
- 첨부 버튼 옆에 "최대 5장" 안내 문구를 상시 노출 (2026-07-28 확정)
- 하단 푸터 좌측: 이미지 첨부 버튼 / 우측: 보내기 버튼

| 답변 대기 | 추가 문의 입력창(이미지 첨부 포함) + 보내기 버튼 | 동일 스레드에 메시지 추가 |
| 답변 완료 | "이 문제가 해결되지 않으셨나요?" 안내 + 새 문의 접수 버튼 | 새 문의 티켓으로 분리 |

- **admin에서 운영자가 완료 처리한 시점**에 해당 문의 스레드는 닫힌 상태로 전환된다.
- 답변 완료 문의는 닫힌 상태로 유지한다. 동일 스레드에 재질문을 추가하지 않는다.
- 완료 문의에서 추가 질문이 필요한 경우, **새 문의 접수 폼**으로 연결하여 별도 티켓으로 처리한다.
- 이 정책은 완료 건의 상태 오염을 방지하고 운영팀의 문의 추적을 명확하게 유지하기 위함이다.

#### 관련 문의 연결 (내 문의 · 골프장 문의 공통, 2026-07-23 반영)

**내 문의**(`myinquiry`)와 **골프장 문의**(`gcinquiry`) 양쪽 모두, 문의 상세에서 "새 문의 접수"로 진입한 경우 기존 문의와의 연관 여부를 admin이 파악할 수 있도록 자동으로 연결 정보를 전달한다.

| 항목 | 정책 |
|---|---|
| 트리거 | 내 문의 / 골프장 문의 상세(답변 완료)의 "새 문의 접수" 버튼 클릭 |
| 자동 연결 | 새 문의 접수 폼 상단에 `관련 문의: {원본 문의 제목} ×` 칩 노출. 원본 문의의 제목·솔루션을 자동으로 전달 |
| 연결 해제 | 칩의 × 클릭 시 연결 해제 — 실제로는 기존 문의와 무관한 새 이슈일 수 있으므로, 사용자가 판단해 제거 가능 |
| 그 외 진입 경로 | 홈 / 가이드 상세 / 문의 목록 상단 버튼 등 상세를 거치지 않은 진입은 연결 정보 없이 일반 신규 문의로 처리 |
| 제출 시 | 연결 유지 상태로 접수하면 admin 문의 상세에 "관련 문의: {원본 문의}" 배너로 노출되어, 운영자가 기존 이슈의 재발/연장 건인지 한눈에 파악 가능. 내 문의 기반 재문의도 골프장 문의와 동일한 배너로 노출됨 (`policy_admin.md` 참고) |


### 문의 답변 번역 정책

번역은 **관리자(CS팀) 언어와 고객 언어가 다른 경우에만** 적용한다.

| 대상 | 번역 적용 여부 |
|---|---|
| 고객이 작성한 문의 내용 | 번역 불필요 (고객 언어 그대로 노출) |
| CS팀이 작성한 답변 | 고객 언어로 번역하여 노출 |

- admin에서 CS팀이 답변을 작성(한국어)하면, 해당 답변은 고객의 언어 설정에 맞게 번역된 결과물로 cs.html에 노출한다.
- 관리자 언어와 고객 언어가 동일한 경우(예: 한국어 고객) 번역 없이 원문을 그대로 노출한다.
- **cs.html(내 문의) 채팅 스레드의 CS팀 답변 원문 노출 (2026-09-22 확정 — 문의 답변에만 적용, 공지·업데이트·가이드의 "원문 비노출" 원칙과는 별개)**: 번역본 아래에 **"원문 보기 ▾" 토글**을 붙여, 클릭하면 원문(한국어)을 접힌 상태에서 펼쳐 볼 수 있다(기본은 접힘). admin이 고객 문의 원문을 "번역 보기"로 접어서 보는 구조와 대칭. 즉시 번역되는 일반적인 답변을 포함해 **모든 CS팀 답변에 적용**된다.

**번역 지연·실패 시 (Q60, 2026-09-22 확정)** — 답변 발송은 즉시 되고 번역은 뒤에서 따로 처리되는데, 번역 API가 5회까지 재시도해도 실패할 수 있다. 이 구간의 노출 방식은 다음과 같다:

| 상태 | 노출 |
|---|---|
| 번역 진행 중(재시도 포함) | **"번역 중"**(2026-09-22 문구 수정 — 기존 "번역 준비 중"에서 축약) 안내만 표시(번역본·원문 모두 미노출, 토글도 없음) |
| 번역 완료 | 번역본 노출 + 위 "원문 보기 ▾" 토글로 원문 확인 가능(일반적인 답변과 동일하게 처리) |
| 5회 재시도 모두 실패 | **번역 실패**하며 원문만 표시(번역본 없음, 토글도 없음 — 이미 원문이 노출돼 있으므로). **경고 아이콘 + "번역에 실패해 원문으로 표시됐어요"** 라벨을 원문 말풍선 아래에 배치(2026-09-22 확정 — 최초 문구 "번역 실패 · 원문"은 관리자용 에러 로그 같은 어투라는 피드백으로 고객 화면에 맞는 대화체로 수정, 같은 날 폰트 크기(10px→12px)·경고 아이콘 추가로 가독성 보강. 2026-10-01 어미 "돼요"→"됐어요"로 재수정 — 실제 반영된 어미에 맞춰 정리) |

자세한 배경은 `policy_admin.md` "번역 지연·실패 시 노출 방식(Q60)" 참고.

### 새 문의 접수 폼

| 항목 | 제한 | 비고 |

| 상세 내용 | 글자 수 제한 없음 | — |

- 상세 내용 영역 아래에 번역 안내 노출: **"담당자에게 자동 번역되어 전달됩니다. 답변도 현재 화면 언어로 번역되어 도착합니다."**
- 번역 안내는 항상 노출한다.

**② 첨부 파일 (2026-07-28 기능 연결)**

- 허용 포맷: JPG · JPEG · PNG · MOV · MP4
- 파일당 최대 50MB, **최대 5개**
- 업로드 영역 클릭 시 파일 선택 창이 열린다 (기존엔 클릭해도 동작하지 않는 플레이스홀더였음)
- 이미지 파일은 썸네일 미리보기, 영상 파일은 아이콘 + 파일명 칩으로 표시. 개별 삭제(×) 가능
- 포맷 오류·용량 초과·5개 초과 시 알럿 안내 후 초과분 제외
- 문의 접수 완료 시 첨부 목록 초기화

**③ 답변 언어 — 항목 제거 (2026-08-05 확정)**

새 문의 접수 폼에 별도 "사용 언어" 선택 필드를 두지 않는다. 답변 번역 언어는 **GNB 헤더에서 현재 선택된 언어**를 그대로 사용한다 (`GNB 언어 선택 정책` 참고). 문의 접수 시점에 언어를 다시 물어보지 않아 입력 단계가 줄어들고, 항상 화면에서 보고 있는 언어와 답변 언어가 일치한다.

### 문의 목록 UI

**상태 필터 탭 (좌측)**

| 탭 | 역할 | 활성 상태 색상 |
|---|---|---|
| 전체 | 전체 문의 표시 | 기본 (회색) |
| 대기 | 답변 대기 문의만 표시 | amber |
| 진행중 (2026-08-18 추가) | 진행중 문의만 표시 — admin이 1회 이상 답변했으나 아직 완료 처리 전 상태(Q29 admin 3단계와 동일 기준, Q39 확정) | 브랜드 블루 |

- 솔루션 필터(셀렉트)는 우측에 배치하며, 상태 탭과 조합 필터링된다.

- **admin과 상태 3단계를 동일하게 유지**(Q39, 2026-08-18 확정) — 기존엔 admin은 대기/진행중/완료 3단계인데 고객 화면은 대기/완료 2단계로 어긋나 있었음. "진행중" 문의를 고객에게도 그대로 보여주는 것으로 확정(대기로 뭉뚱그리지 않음).

**레이아웃**
```
[전체] [대기] [진행중] [완료]          [전체 솔루션 ▼]
```

**빈 상태 안내**

- 필터 결과가 0건이거나 접수된 문의가 없을 때 리스트 영역 내 안내 문구를 표시한다.
- 안내 문구: "접수된 문의가 없습니다. 문제가 있으시면 새 문의를 접수해 주세요."
- 내 문의 · 골프장 문의 모두 동일하게 적용한다.

**골프장 문의 문의자 표시**

- 골프장 문의 목록 및 상세에서 문의를 접수한 사람은 **문의자**로 표기한다. ("접수자" 사용하지 않음)
- 문의자 이름은 **클라우드에 설정된 이름**을 사용한다.

## 이미지 확대 보기(라이트박스) 정책 (2026-07-23 반영)

이미지를 클릭하면 배경을 딤 처리하고 원본 크기로 확대해 보여준다. **조회(열람) 시점에만 적용**하며, 새 문의 접수·답변 작성 등 등록 단계의 첨부 미리보기(섬네일)에는 적용하지 않는다.

| 위치 | 적용 대상 |
|---|---|
| 문의 상세 채팅 스레드 (내 문의 / 골프장 문의) | 고객 본인이 보낸 이미지 + CS팀이 전달한 답변 이미지 모두 클릭 시 확대 |
| 솔루션 가이드 상세 본문 이미지 | 클릭 시 확대 |
| 공지사항 상세 본문 이미지 | 클릭 시 확대 |
| (제외) 새 문의 접수 / 추가 문의 입력의 첨부 미리보기 섬네일 | 등록 단계이므로 확대 미적용 |

- 닫기: 딤 배경 클릭 / 닫기 버튼 / Esc 키
- admin 화면(`smartscore_admin_v0.3.html`)에서는 **사용자·골프장 관계자가 보낸 이미지만** 확대 대상이며, 관리자 자신이 보낸 답변 이미지는 확대 대상에서 제외한다. (자세한 내용은 `policy_admin.md` 참고)
- **첨부 이미지가 2장 이상인 메시지는 좌우 화살표 버튼 클릭으로 넘겨볼 수 있다**(2026-09-08 확정 — **키보드 ←/→ 이동은 미제공**). 화면 하단에 `N / M` 카운터 노출. 1장뿐인 메시지·공지사항/가이드 본문 이미지는 기존과 동일하게 화살표 없이 단일 확대만 제공. 자세한 판별 기준은 `policy_admin.md` "첨부 이미지 2장 이상 — 좌우 넘겨보기" 참고

## 솔루션 가이드 정책

### 목록 구조

- 솔루션 가이드는 **3단계 탐색 구조 없이 플랫(flat) 목록**으로 제공한다.
- 목록 상단에 솔루션 탭, 유형 필터, 분류 필터를 제공한다.
- 필터 순서: **유형 필터 → 분류 필터** 순으로 배치한다.

### 페이지네이션 (2026-07-28 반영)

- 목록 하단에 **페이지네이션**을 제공한다. 1페이지당 **30개** 노출.
- 필터(솔루션 탭·유형·분류) 변경 시 1페이지로 초기화되며, 필터링된 결과 기준으로 페이지가 계산된다.
- 전체 건수 정보 없이 "이전 / 페이지 번호 / 다음" 버튼만 콘텐츠 영역 기준 **중앙 정렬**로 노출한다. 1페이지만 있어도 항상 노출한다.

### 솔루션 탭

| 탭 | 설명 |

| 전체 | 모든 솔루션의 가이드 표시 |

- 상단에 "가이드 목록" 뒤로 가기 버튼을 제공한다.
- 상세 하단에 "이 가이드로 해결이 안 되셨나요?" 문의 접수 유도 배너를 표시한다.
- 홈 솔루션 그리드에서 특정 솔루션 카드를 클릭하면 해당 솔루션 탭이 선택된 상태로 가이드 목록 페이지로 이동한다.

## 자주 묻는 질문 정책 (Q61, 2026-09-28 확정)

FAQ는 별도 콘텐츠가 아니라 **admin에서 "FAQ 지정"으로 표시한 솔루션 가이드**로 구성된다(생성 방식은 `policy_admin.md` "자주 묻는 질문(FAQ)" 참고 — 가이드 문서 경로만 존재, 문의 답변 경로는 미확정).

| 항목 | 정책 |
|---|---|
| 목록(질문) | FAQ 지정된 가이드의 제목을 질문으로 노출, 솔루션 배지 함께 표시 |
| 펼침 답변 | **가이드 상세와 동일하게 전문을 노출**한다(2026-09-28 확정 — 이전엔 "첫 문단만 보여주고 링크로 상세 이동" 형태였으나, 솔루션 가이드와 동일한 내용을 그대로 보여주는 것으로 변경). 본문 + 해결 절차(있는 경우)까지 동일하게 조립 |
| "솔루션 가이드에서 보기" | 클릭 시 **실제 해당 가이드 상세 페이지로 이동**한다(2026-09-28 확정 — 이전엔 텍스트만 있고 클릭해도 동작하지 않았음). "함께 보면 좋은 가이드"와 동일한 이동 로직 재사용 |
| 솔루션 필터 | FAQ 페이지 상단 솔루션 탭으로 필터링(전체/솔루션별) |

## 홈 화면 정책

### 홈 섹션 정렬 기준

홈 화면에 노출되는 모든 섹션의 게시물은 **등록일 기준 내림차순(최신순)**으로 표시한다.

| 섹션 | 정렬 기준 |
|---|---|
| 공지사항 | 공지 등록일 내림차순 |
| 업데이트 | 업데이트 등록일 내림차순 |
| 내 문의 | 문의 접수일 내림차순 |
| 골프장 문의 | 문의 접수일 내림차순 |
| 자주 묻는 질문 | 가이드 등록일 내림차순 |

- 실제 서비스에서는 서버 응답 시 각 섹션의 정렬 조건을 적용하여 반환한다.

### 홈 섹션 노출 개수 (2026-08-04 확정)

| 섹션 | 노출 개수 |
|---|---|
| 공지사항 | 4개 |
| 업데이트 | 4개 |
| 내 문의 | 3개 |
| 골프장 문의 | 3개 |
| 자주 묻는 질문 | 6개 (2열 × 3행) |

- 각 섹션 헤더의 "전체보기"로 이동하면 전체 목록을 확인할 수 있다.

### 홈 섹션 빈 상태 안내

각 섹션에 노출할 게시물이 없을 때, 섹션 영역 내에 안내 문구를 표시한다. 섹션 헤더는 유지하고 콘텐츠 영역에만 빈 상태를 노출한다.

| 섹션 | 안내 문구 | CTA |
|---|---|---|
| 공지사항 | 등록된 공지사항이 없습니다. | 없음 |
| 업데이트 | 등록된 업데이트가 없습니다. | 없음 |
| 내 문의 | 접수된 문의가 없습니다. | 새 문의 접수하기 버튼 |
| 골프장 문의 | 접수된 문의가 없습니다. | 없음 |
| 자주 묻는 질문 | 등록된 FAQ가 없습니다. | 없음 |

- 내 문의는 빈 상태에서도 **새 문의 접수하기** 버튼을 노출하여 바로 접수로 연결한다.
- 그 외 섹션은 안내 문구만 표시하며 별도 CTA 없음.

## GNB 검색 정책 - ⚠️ 백로그, 오라클 기반 AI 검색으로 추후 진행 예정 (2026-10-01 명시)

아래는 목표 스펙이며, 현재 cs.html에는 **미구현 상태로 주석 처리**되어 있다(GNB 검색 버튼·검색 패널·홈 히어로 검색창 모두 `<!-- [BACKLOG] -->` 처리). 향후 **오라클(Oracle) 기반 AI 검색**으로 구현할 예정이며, 그 전까지는 아래 스펙대로 동작하지 않는다.

- 버튼 클릭 시 GNB 아래로 검색 패널이 슬라이드 다운 방식으로 펼쳐진다.
- 검색 패널이 열리면 입력 필드에 자동 포커스된다.
- 검색 실행 시 검색 결과 페이지(`page-sr`)로 이동하며, 홈·검색 결과 페이지의 검색창 값과 GNB 검색 입력값은 동기화된다.
- 검색 패널은 닫기(X) 버튼 또는 버튼 재클릭으로 닫을 수 있다.
