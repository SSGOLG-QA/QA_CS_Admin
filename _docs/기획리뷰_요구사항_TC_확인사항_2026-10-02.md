## 1. 요구사항 분석 요약

### 1-1. 시스템 구성
- **Front(고객, 라이브)**: `customer-success-td.smartscore.kr` — 골프장 관계자용 조회 화면(Vue SPA). 공지/업데이트/가이드/FAQ 조회 + 문의.
- **Admin(운영자)**: 내부관리자 `cc.smartscore.kr/ss/mng` '고객성공' 메뉴(1차 국내 담당자 전용). 콘텐츠 CRUD + 문의 답변. (리뷰 자료 `smartscore_admin_v0.3.html`은 정적 프로토타입)

### 1-2. 연계 공식 — front 노출은 admin 설정 5조건의 AND
```
front 노출 = 노출여부(ON) ∧ 게시기간(유효/무기한) ∧ 적용국가 ∈ {고객국가, 🌍전체}
           ∧ 상태(공지·가이드=노출 / 업데이트=반영완료) ∧ 솔루션(지정/전체)
표시내용   = 고객 언어 번역본 (저장형: 원문 저장 → 일괄 번역 → 저장)
```
- **적용국가 = 노출 대상 + 번역 언어** 이중 역할.
- 업데이트 `반영완료`만 front 노출(반영대기=admin 전용). 공지·가이드는 `노출`만.

### 1-3. 콘텐츠별 핵심
- **공지사항**: 솔루션 단일·적용국가·게시기간(만료 시 OFF, 무기한 가능). front 날짜는 라벨 없이 날짜(범위)만.
- **업데이트**: 솔루션 복수 섹션(포함 모든 탭 노출)·상태텍스트 숨김·더보기 10+10.
- **솔루션 가이드**: 유형3·분류6(고정)·태그(필수)·FAQ 지정 토글·관련 가이드 최대 5개(양방향).
- **FAQ**: 별도 생성 아님 — 가이드 `FAQ 지정`으로 구성(읽기전용). 질문=가이드 제목, 답변=가이드 전문.
- **문의**: 양방향 스레드. 상태 3단계(답변 대기→진행중→답변 완료). 10초 폴링 실시간. 완료 시 스레드 잠금→새 문의로 분기.

### 1-4. 확정 사항 (재질의 방지 — 리뷰에서 다시 묻지 않기)
| 확정 | 근거 |
|---|---|

## 2. TC 작성 현황 & 필요사항

### 2-1. 현황
| 화면 | TC(엑셀) | 자동화 스위트 | 라이브 검증 | 비고 |
|---|:---:|:---:|:---:|---|
| 공지사항 | ✅ v2(프론트 22 + **연계 16**) | ✅ runNotice + **연계 L01~L06** | ⚠️ 연계 체크 재실행 필요 | 연계 관점 반영 완료 |
| 업데이트 | ✅ (28행) | ✅ runUpdate | ✅ PASS 13/0 (연계 체크 미반영) | 연계 섹션 추가 여지 |
| 솔루션 가이드 | ❌ | ❌ | — | 미착수 |
| FAQ | ❌ | ❌ | — | 미착수(가이드 연동) |
| 문의(내문의·골프장문의·새문의) | ❌ | ❌ | — | 미착수(양방향·상태머신) |
| 홈 | ❌ | ❌ | — | 미착수(집계 프리뷰) |

### 2-2. TC 작성 원칙 (연계 관점 반영)
1. **각 화면 TC에 "연계 검증" 섹션**을 둔다 — admin 설정(노출여부·기간·국가·솔루션·상태)이 front 노출 공식(§1-2)에 정합한지 관측형으로 확인(공지 TC v2가 템플릿).
2. **관측형 한계 명시**: admin 목업=백엔드 없음, 실 admin=쓰기 시 실데이터 파괴 → **admin에서 생성→front 확인하는 진짜 E2E는 자동화로 닫을 수 없음**. front 관측값이 공식에 맞는지 대조하는 방식.
3. **검증 가능 vs 불가 투명 분리**: 국가 전환(언어 선택기 한계)·수정저장 결함 등은 **투명 SKIP**(사유 명시, 커버리지 착시 방지).
4. **2축**: AS-IS PASS/FAIL + 기획-구현 차이(diff) 추적.
5. **비파괴**: 조회·필터·읽기만. 새 문의 접수·완료 처리·저장·삭제 클릭 금지.

### 2-3. 필요사항 (리뷰 결과에 의존)
> 아래 §3 확인 항목의 결론이 TC **예상결과를 바꾼다**. 특히 — 시간대 표시(공지·업데이트 날짜 예상결과), 상태 라벨 통일(문의 TC), 솔루션명·정렬(공지·업데이트·가이드), 새 문의 "전체" 허용(새 문의 TC). 리뷰 확정 후 해당 TC 반영.

## 3. 기획리뷰 확인·문의 리스트

> 각 항목: **질문 / 배경(근거) / 미확인 시 리스크**. ✅=확정 시 TC 반영.

### 🔴 P1 — 리뷰에서 반드시 결론

**Q1. 해외 고객 시간대 표시 기준 + 언어↔국가 매핑**
- 배경: 현재 한국 외 국가도 KST 원본+"KST" 라벨만 표시(현지 환산 보류, ISSUE-079). front 전환 스위치가 **언어(8)** 라 **국가(11)** 와 1:1 매핑 불가(English를 필·말·싱·미 공유).
- 질문: 국가 선택기 도입 vs 언어별 대표국가 근사 vs KST 고정 유지 중 무엇? 언어↔국가 매핑을 어떻게 확정?
- 리스크: 전 해외 국가가 게시·만료·문의 시각 오인. (시간대·태그번역·번역범위의 공통 전제)

**Q2. 지원 언어 확정**
- 배경: policy_admin "기획 보완 필요"에 **지원 언어 확정** 미결. 번역 저장형·태그 번역·시간대 매핑의 선행 조건.
- 질문: 1차 지원 언어 목록 확정? (운영 11개국 ↔ 8개 언어 선택기 정합)
- 리스크: 번역 대상/범위 미확정 → 콘텐츠 다국어 TC 설계 불가.

**Q3. 수정 저장 미반영 결함 — 범위·일정**
- 배경: 수정 저장이 **제목·본문만** 반영, 노출여부·게시기간·적용국가·솔루션은 미반영(2026-09-02, 1차 한정 결함). 신규 등록은 정상.
- 질문: 나머지 필드 반영은 언제/어느 범위로 확장? (admin↔front 드리프트 최대 원천)
- 리스크: admin에서 OFF/국가변경해도 front에 안 먹혀 운영 사고.

**Q4. 알림 소멸 규칙 상충**
- 배경: "전 유형 7일 자동소멸"(ISSUE-084) vs "답변 대기=상태 해소 시 즉시소멸"(ISSUE-092) 상호 배타.
- 질문: 액션형 알림(답변 대기 등)은 7일 유지인가 조건 해소 즉시 소멸인가? 우선순위는?
- 리스크: 완료 처리한 문의의 알림 잔존/조기소멸로 운영 혼선.

**Q5. 새 문의 "전체" 솔루션 접수 허용 여부**
- 배경: 솔루션 선택은 "필수 11개"인데 실구현 SELECT에 "전체"가 옵션으로 포함(12).
- 질문: "전체"로 접수 허용? 허용 시 담당 라우팅은?
- 리스크: 라우팅 불가 문의 발생.

### 🟡 P2 — 가능하면 리뷰에서

**Q6. 솔루션명 "무전" vs "무전기" 정본**
- 배경: 정책/tag_pool/admin 목업=**무전**, 실 front 탭·배지=**무전기**(기능 정상, 명칭만 차이).
- 질문: 어느 표기가 정본? 전 화면(admin·front) 통일할 것인가?
- 리스크: 명칭 불일치 혼선. (TC는 현재 diff로 추적 중)

**Q7. 솔루션 나열 순서 통일**
- 배경: 솔루션 순서가 3곳 상이 — admin 필터 / front 가이드 탭 / front 홈 그리드(구성 11개는 동일, 순서만 다름).
- 질문: 나열 순서를 하나로 통일? 기준 순서는?
- 리스크: 화면 간 순서 불일치(결함은 아닐 수 있으나 사용성).

**Q8. FAQ 안내문구의 "문의 답변" 출처 표현**
- 배경: FAQ 구성 출처는 "가이드 FAQ 지정"인데 안내문구는 "가이드 문서와 **문의 답변** 중…"로 미구현(1차 제외, ISSUE-108) 기능을 암시.
- 질문: 문구를 1차 범위(가이드 지정만)에 맞게 수정?
- 리스크: 미구현 기능 약속 → 고객 기대 불일치.

**Q9. 번역 실패 재시도 규칙**
- 배경: "5회 재시도 후 원문만 노출"의 재시도 **시점**(접수 시 vs 조회 시)과 cs·admin 상태 표기 동기화 불명확.
- 질문: 재시도 시점·주체·상태 동기화 규칙은?
- 리스크: 재시도 중 고객·admin이 서로 다른 상태를 봄.

**Q10. 목록 정렬 서버 강제**
- 배경: "등록일 내림차순" 확정이나 목업 실제 행 순서가 규칙과 불일치·강제정렬 로직 부재(ISSUE-063).
- 질문: 서버에서 등록일 내림차순 강제? (공지·업데이트 공통)
- 리스크: 실서비스 정렬이 규칙과 다름.

**Q11. 태그 번역 방식**
- 배경: 태그는 검색·필터 키라 단순 문자열 번역 불가 → 언어별 컬럼 마스터테이블 필요(policy_admin #2 미결).
- 질문: 다국어 환경 태그 저장·표시·필터 방식은?
- 리스크: 다국어 front에서 태그 거동 미확정 → 가이드 TC 다국어 보류.

### 🟢 P3 — 시간 되면 / 추후

**Q12. 문의 완료 배지 색상** — admin gray vs front green(문서상). 통일 여부. (경미)
**Q13. 상태 라벨 통일** — 홈 stat "답변 대기/답변 완료" vs 목록 탭 "대기/완료" 혼재. 전 화면 "답변 대기/진행중/답변 완료" 통일?
**Q14. 번역문 길이 초과 표시** — 번역문이 원문(50자)보다 길 때 제목/이미지설명 줄바꿈·말줄임·툴팁 규칙.

**Q16. admin 실서비스(mng) QA 접근·쓰기 범위** — 자동화 스코프. 연계 E2E(생성→확인) 가능 여부 결정.
**Q17. 해외/국내 기능 차이·권한 정의** — policy_admin 미결. 2차 범위 확인.
**Q18. B2B 솔루션 탭 노출** — 솔루션 필터 12탭이 골프장 도입 솔루션과 무관하게 항상 12개인가, 도입분만인가(현 실구현=항상 12).

## 4. 리뷰 후 QA 액션 (예정)
1. P1 확정 결과를 공지/업데이트 TC **예상결과에 반영**(특히 시간대·정렬·솔루션명).
