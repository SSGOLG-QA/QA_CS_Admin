# 솔루션 가이드 태그 풀

가이드 등록 시 사용되는 태그의 계층 구조 정의.

---

## 구조 개요

```
1depth  솔루션 공통 대분류 (UI 미노출 — 데이터 구조·통계용)
  └─ 2depth  솔루션별 중분류 (UI: 섹션 헤더로만 표시, 선택 불가)
       └─ 3depth  실제 태그 (UI: 클릭 가능 칩, 가이드에 저장되는 값)
```

**UI 노출 원칙**
- 1depth: 화면에 노출하지 않음. 백엔드 분류·통계 집계용
- 2depth: 섹션 헤더 텍스트로만 표시 (클릭·선택 불가)
- 3depth: 클릭 가능한 칩으로 표시. 이 값이 가이드에 실제 저장됨

**커스텀 태그**
- 태그는 반드시 풀에서 선택. 직접 입력 기능 미제공
- 풀에 없는 태그가 필요한 경우 운영팀 요청 → 관리자가 태그 풀에 추가 후 사용

---

## 1depth 공통 분류

| 코드 | 명칭 | 설명 |
|---|---|---|
| `ERROR` | 오류 · 장애 | 기능이 정상 작동하지 않는 오류·장애 상황 |
| `FUNC` | 기능 · 조작 | 정상적인 기능 사용법 및 조작 관련 |
| `DEVICE` | 기기 · 연결 | 하드웨어 기기, 네트워크 연결 관련 |
| `DATA` | 데이터 · 연동 | 데이터 조회, 집계, 외부 시스템 연동 |
| `CONFIG` | 설정 · 환경 | 초기 설정, 권한, 환경 구성 관련 |
| `ETC` | 기타 | 위 분류에 해당하지 않는 커스텀 태그 |

## 개발 구현 참고

### 데이터 스키마 (예시)

```json
{
  "tag": "결제 실패",
  "depth1": "ERROR",
  "depth2": "오류 유형",
  "solution": "카트내결제"
}
```

### 가이드 저장 시 태그 필드

```json
{
  "guide_id": "...",
  "tags": ["결제 실패", "E-204", "카드 인식 불가"]
}
```

3depth 값(태그 문자열)만 가이드에 저장. 1·2depth는 태그 마스터 테이블에서 조회.

### 태그 마스터 테이블 구조 (권장)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `tag_id` | INT | PK |
| `tag_name` | VARCHAR | 3depth 태그명 (화면 표시 및 저장값) |
| `depth2_name` | VARCHAR | 2depth 섹션명 |
| `depth1_code` | VARCHAR | 1depth 코드 (ERROR / FUNC / DEVICE / DATA / CONFIG / ETC) |
| `solution` | VARCHAR | 솔루션명. NULL이면 전체 공통 태그 |
| `sort_order` | INT | 섹션 내 노출 순서 |
| `is_active` | BOOL | 비활성화 시 추천 목록에서 제외 |

### 커스텀 태그 처리

풀에 없는 값을 직접 입력한 경우:
- `depth1_code`: `ETC`
- `depth2_name`: `직접입력`
- `solution`: 해당 가이드의 솔루션 값 상속

---

## 추가 운영 정책

- 태그 풀은 운영팀 요청 시 마스터 테이블에서 관리자가 추가·수정·비활성화
- 동일 태그명이 솔루션별로 다른 맥락을 가질 경우 `solution` 컬럼으로 분리 관리
- 통계 집계 시 1depth 코드 기준으로 솔루션 横 비교 가능
  - 예: 전체 솔루션의 `ERROR` 태그 비율 → 솔루션별 오류 발생 빈도 파악
